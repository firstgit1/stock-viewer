# 数据看板 · 部署说明

这份文档说明当前网站是怎么上线的，以及别人问「你们怎么部署的」时可以怎么回答。

---

## 一句话概括

这是一套 **前端静态托管 + 无服务器 API + 托管 Redis** 的架构，也可以叫 **Serverless / JAMstack 风格部署**。

- **前端**：打包成静态文件，部署到 **Vercel**
- **登录/注册接口**：写成 Vercel **Serverless Functions**（无服务器函数），和前端同一个项目一起部署
- **用户数据**：存在 **Upstash Redis**（云端托管的 Redis，按用量计费，有免费额度）

不需要自己买云服务器、装 Nginx、装 MySQL，也不用自己维护一台 Redis。

---

## 这种方法叫什么？

| 常见叫法 | 含义 |
|---------|------|
| **Serverless 部署** | 业务逻辑跑在云平台提供的「函数」里，不用长期占着一台服务器 |
| **JAMstack** | 前端预构建（JavaScript + API + Markup），数据和动态能力走 API |
| **BaaS / 托管后端服务** | Redis 这类能力直接用厂商托管服务（这里是 Upstash） |
| **Git 驱动部署（GitOps 的简化版）** | 代码推到 GitHub，Vercel 自动构建并发布 |

对外介绍时，比较好懂的说法是：

> 我们用 **Vercel 做前端和无服务器接口部署**，用 **Upstash 做托管 Redis 存用户账号**，通过 **GitHub 推送自动上线**。

---

## 整体结构（别人问「具体是什么」时用）

```text
用户浏览器
    │
    ▼
Vercel（CDN + 静态网站）
    │  打开页面：HTML/JS/CSS（Vue 打包产物）
    │
    ├─ /api/login、/api/register、/api/me、/api/logout
    │     └─ Vercel Serverless Functions（Node.js）
    │              │
    │              ▼
    │         Upstash Redis（存用户名、密码哈希）
    │
    └─ 数据等
          └─ 直接请求第三方 HTTP API（浏览器侧调用）
```

### 1. 前端包部署（Vercel）

| 项目 | 说明 |
|------|------|
| 是什么 | Vue 3 + Vite 项目，执行 `npm run build` 后生成 `dist/` 静态文件 |
| 部署到哪 | [Vercel](https://vercel.com) |
| 怎么上去的 | GitHub 仓库关联 Vercel；推送到 `main` 后自动 Build + Deploy |
| 线上地址示例 | `https://stock-viewer-kappa.vercel.app` |
| 特点 | 全球 CDN 加速；HTTPS 自动配置；不用自己管服务器 |

对应概念：**静态站点托管 / Frontend Hosting**。

### 2. 登录注册接口（仍在 Vercel，不是另一台服务器）

| 项目 | 说明 |
|------|------|
| 是什么 | 项目里的 `api/*.js`，例如 `api/login.js`、`api/register.js` |
| 部署到哪 | 和前端同一 Vercel 项目，路径形如 `/api/login` |
| 运行方式 | 有请求时才启动函数，用完即释放（Serverless） |
| 会话方式 | 登录成功后发 HttpOnly Cookie（签名会话），不是把密码放前端 |

对应概念：**Serverless Functions / FaaS（Function as a Service）**。

### 3. Redis 数据库（Upstash）

| 项目 | 说明 |
|------|------|
| 是什么 | 托管 Redis，用来存注册用户（用户名唯一、密码用 scrypt 哈希） |
| 部署到哪 | [Upstash](https://upstash.com)，本项目选用 AWS Singapore 区域 |
| 「部署」含义 | 不是自己安装 Redis，而是在控制台「创建 Database」，拿到 REST URL/TOKEN |
| 怎么连上 | 在 Vercel 配环境变量，函数运行时读取并访问 Upstash |
| 免费额度 | Free Tier（命令次数、容量有限，个人小项目通常够用） |

对应概念：**Managed Redis / Database as a Service（DaaS）**。

注意：这里的 Redis **不是**传统意义上「买台机器自己装 Redis」；  
也 **不是** 把数据库文件上传到 Vercel。而是使用云厂商已经运维好的 Redis 服务。

## 环境变量（把两边「接起来」的关键）

在 Vercel → Project → Environment Variables 配置：

| 变量名 | 作用 |
|--------|------|
| `AUTH_SECRET` | 给登录 Cookie 做签名，防止伪造 |
| `UPSTASH_REDIS_REST_URL` | Upstash REST 地址 |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash REST 密钥 |
| `AUTH_USER` / `AUTH_PASS`（可选） | 环境变量里的管理员账号，可不配 |

改环境变量后需要 **Redeploy**，新配置才会生效。

本地开发可用 `.env.local`；未配 Upstash 时，本地会把用户写到 `.data/users.json`（仅开发用，不会用于生产）。

## 实际操作流程（我们是怎么部署上去的）

### A. 前端 + API（一次搞定）

1. 代码放在 GitHub：`firstgit1/stock-viewer`
2. 在 Vercel 导入该仓库，框架选 Vite/Vue，保持默认构建设置
3. 之后每次 `git push` 到 `main`，Vercel 自动：
   - 安装依赖
   - 执行构建
   - 发布静态资源
   - 同步发布 `/api/*` 无服务器函数

所以：**前端包和登录 API 是同一次 Vercel 部署完成的**，不是两套独立服务器。

### B. Redis（单独在 Upstash 创建）

1. 打开 Upstash 控制台 → Create Database
2. 名称如 `stock-viewer`，区域选 **Singapore (`ap-southeast-1`)**（越南访问较近）
3. 选择 Free Tier
4. 在 Connect → REST 复制 URL 和 TOKEN
5. 粘贴到 Vercel 环境变量
6. Redeploy 一次

所以：**Redis 不是跟前端一起 `git push` 上去的**，而是在 Upstash 控制台创建服务，再通过环境变量连接到 Vercel。

## 别人问时，可以这样回答

### 短答（30 秒）

> 前端用 Vue 打包后部署在 Vercel；登录注册接口也写成 Vercel 的 Serverless Functions，和前端同一个仓库自动发布。用户账号存在 Upstash 的托管 Redis 里，通过环境变量连接。整体是 Serverless 架构，不自建服务器。

### 稍完整（1–2 分钟）

> 我们没有自己租 ECS 装 Nginx/MySQL。  
> 代码推到 GitHub 后，Vercel 负责构建和托管前端静态资源，同时把 `api` 目录部署成按需运行的函数，处理登录注册。  
> 用户数据用 Upstash Redis 存，密码做哈希，用户名不可重复。  
> Vercel 负责「网站和接口上线」，Upstash 负责「账号数据存储」，两边用环境变量打通。

### 对比传统方式（显专业）

| 传统方式 | 我们现在的方式 |
|---------|----------------|
| 买云服务器，装 Nginx | Vercel 静态托管 + CDN |
| 自己跑 Node/Java 常驻进程 | Vercel Serverless Functions |
| 自己装 MySQL/Redis | Upstash 托管 Redis |
| 手动 FTP/SSH 发布 | GitHub push 自动部署 |

## 仓库里和部署相关的关键文件

| 路径 | 作用 |
|------|------|
| `package.json` | 依赖与 `build` 脚本 |
| `vercel.json` | SPA 路由回退；避免把 `/api` 误重写到前端 |
| `api/*.js` | 登录/注册/登出/当前用户 接口 |
| `lib/users.js` | 用户读写、密码哈希、Upstash/本地存储 |
| `.env.example` | 环境变量模板（不含真实密钥） |

---

## 安全与边界（回答「靠谱吗」时可用）

- 密码不明文存储，使用 scrypt 哈希
- 会话用 HttpOnly Cookie，降低 XSS 偷 Cookie 的风险
- 密钥只放在 Vercel/Upstash，不提交进 Git
- 适合个人/小团队工具站；若以后用户量很大或要复杂权限，可再升级到正式数据库（如 Postgres）和更完整的账号体系

## 常见问题

**Q：Redis 也是「部署」到 Vercel 了吗？**  
A：不是。Redis 在 Upstash；Vercel 只是通过网络调用它。

**Q：前端和后端是分开两个项目吗？**  
A：不是。一个 Git 仓库：`src` 是前端，`api` 是无服务器接口，一起由 Vercel 发布。

**Q：为什么选这个方案？**  
A：上线快、运维少、有免费额度、和 GitHub 集成好，适合这类轻量看板。

**Q：本地怎么跑？**  
A：配置 `.env.local` 后执行 `npm run dev`。本地可不配 Upstash，用户会落到 `.data/users.json`。
